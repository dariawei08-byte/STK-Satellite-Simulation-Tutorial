STK 12.2 入门实操（一）：卫星对地可见性分析与传感器视场角对比

软件版本： STK 12.2

实验内容： 卫星可见性分析、传感器设置、不同视场角下的可见性对比

1. 实验说明

这篇笔记从已经建立好的 STK 场景开始，主要记录可见性分析和传感器设置的操作过程。之前创建场景、卫星轨道以及地面目标时没有保留完整截图，因此这里不重复展开。

实验场景为 "STK_Test"，包含：

- "Satellite1"：用于练习的卫星
- "Facility1"：位于新西兰惠灵顿附近的地面目标
- 仿真时间：2026年10月31日03:00至11月1日03:00（UTCG）

本次主要想弄清两个问题：卫星能看到地面目标，是否意味着传感器也能看到？改变传感器视场角后，计算结果会有什么变化？

2. 卫星与地面目标的可见性分析

2.1 打开 Access 工具

在左侧 Object Browser（对象浏览器）中找到 "Satellite1"，通过右键菜单打开 Access（可见性分析）。

在 Access 窗口中选择 "Facility1"，计算时间范围保持默认的 Use Object Time Periods（使用对象时间范围），点击 Compute（计算）。



2.2 查看分析报告

点击 Reports 下的 Access，生成 Access Summary Report（可见性汇总报告）。



根据报告，24小时内计算得到7个几何可见窗口。

指标| 计算结果
可见次数| 7次
最短可见时长| 394.498 s
最长可见时长| 725.412 s
平均可见时长| 640.674 s
累计可见时长| 4484.716 s

这里的 Access 反映的是当前约束下卫星和地面点之间的几何可见性，并不意味着卫星上的相机已经成功拍摄目标。

3. 添加卫星传感器

3.1 创建 Sensor

打开 Insert STK Objects（插入 STK 对象），在 Attached Objects（附属对象）中选择 Sensor（传感器），选择 Define Properties（定义属性）。

在随后出现的 Select Object（选择对象）窗口中选择 "Satellite1"，表示将传感器安装在这颗卫星上。

【插图03：选择 Satellite1 作为传感器所属对象】

完成后，左侧对象浏览器应出现 "Satellite1 → Sensor1" 的层级结构。

3.2 设置传感器视场角

进入 "Sensor1 → Basic → Definition"。

设置以下参数：

参数| 设置值
Sensor Type（传感器类型）| Simple Conic（简单圆锥）
Cone Half Angle（圆锥半角）| 10°

Cone Half Angle 表示圆锥中心轴与边缘之间的夹角，因此半角为10°时，完整锥角为20°。

【插图04：Sensor1 的 Definition 设置界面】

3.3 检查传感器指向

进入 "Sensor1 → Basic → Pointing"。

本次实验采用以下设置：

- Pointing Type（指向类型）：Fixed（固定指向）
- Orientation Method（方向描述方式）：Az-El（方位角—仰角）
- Azimuth（方位角）：0°
- Elevation（仰角）：90°

【插图05：Sensor1 的 Pointing 设置界面】

这里的 Fixed 是相对于卫星局部坐标系固定，传感器在空间中的实际指向还与卫星姿态有关。

4. 传感器半角为10°时的可见性分析

完成传感器设置后，右键点击 "Sensor1"，打开 Access，选择 "Facility1"，点击 Compute。

随后打开 Reports → Access，查看计算报告。

【插图06：显示 No Access Found 的报告】

结果显示：

No Access Found（未找到可见时间窗口）

这一结果与之前的7次几何可见窗口并不矛盾。

卫星虽然在部分时段能够看到地面目标，但传感器还受到视场角和指向的限制，目标可能始终不在传感器的观测范围内。

为了进一步判断视场角的影响，接下来只修改圆锥半角，进行一次对照实验。

5. 将圆锥半角改为45°

进入 "Sensor1 → Basic → Definition"，把 Cone Half Angle 从10°修改为45°，其他参数保持不变。

重新计算 "Sensor1 → Facility1" 的 Access。

【插图07：45°圆锥半角下的 Access 分析报告】

这次计算得到了2个可见窗口：

次数| 开始时间（UTCG）| 结束时间（UTCG）| 持续时间
1| 10月31日07:29:53| 10月31日07:30:59| 66.482 s
2| 11月1日00:30:57| 11月1日00:33:08| 131.030 s

累计可见时间约为197.512秒，即3.29分钟。

与10°时的结果相比，扩大传感器视场后，原本没有可见窗口的情况变成了2次。

由此可以看出，在本次仿真场景及其他参数不变的情况下，视场角会显著影响传感器对指定地面目标的可见性。

但视场角扩大并不意味着实际成像质量一定提高，真实光学载荷还需要考虑地面分辨率、光照和信噪比等因素。

6. 显示传感器在二维地图上的投影

为了直观观察卫星对地面的覆盖情况，进入：

"Sensor1 → 2D Graphics → Projection"

确认 Show Projection on 2D Map（在二维地图上显示投影）已经勾选。

本次其他设置保持默认，包括：

- Show Intersections：Central Body（中心天体）
- Persistence Time：0 sec（持续显示时间为0秒）

【插图08：2D Graphics → Projection 设置界面】

保存设置后，回到主界面，将仿真时间调整为：

"31 Oct 2026 07:30:00"

这个时间处于第一个传感器可见窗口内。

观察二维地图，可以看到 Satellite1、Facility1 以及相关的投影和轨迹图形。

【插图09：07:30时刻的二维地图，包含 Satellite1 和 Facility1】

需要注意，地图上可能同时显示轨道、地面轨迹、传感器投影等元素。不能仅根据线条颜色判断其含义，需要结合对象的图形显示设置。

7. 实验结果对比

将本次的计算结果汇总如下：

分析对象及条件| 可见次数| 累计可见时间
Satellite1 → Facility1| 7次| 4484.716 s
Sensor1 → Facility1，半角10°| 0次| 0 s
Sensor1 → Facility1，半角45°| 2次| 197.512 s

通过这次实验，可以直观看到卫星几何可见性与传感器可见性之间的区别。

卫星能看到目标，并不代表搭载的传感器一定能够覆盖目标。传感器的视场角和指向方式会进一步限制可见窗口。

本次分析尚未考虑实际光学成像质量、云层遮挡等因素，因此不能直接将计算结果等同于真实卫星的有效成像次数。

8. 操作过程中遇到的问题

（1）找不到 Access 工具

需要注意左侧选中的对象。分析卫星可见性时选择 Satellite1，分析传感器可见性时选择 Sensor1。

Analysis Workbench（分析工作台）与 Access（可见性分析）不是同一个工具。

（2）出现 No Access Found

这不一定是计算错误。需要检查仿真时间范围、传感器视场角、指向设置及目标位置等参数。

本次将圆锥半角由10°改为45°后，就计算出了2个可见窗口。

（3）地图上看不到传感器覆盖范围

可以检查 Projection 设置，并把仿真时间直接调整到 Access 报告中的可见窗口内，再观察地图。

本次完成了 STK 中的卫星可见性分析、传感器创建、视场角设置以及仿真结果对比。
